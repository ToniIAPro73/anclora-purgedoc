## Decisions

1. **Git policy.** Branches `development`, `staging`, `production`, `main` exist; `development`
   is the working and GitHub default branch. Feature branches are disallowed unless Toni orders them.
2. **Promotion.** `development → staging → production → main`, only through the manual
   `promote.yml` workflow: fast-forward only, no merge/rebase/cherry-pick/force push, and only
   for a source SHA with a successful `CI / Development` run. Agents never promote on their own.
3. **CI.** `ci.yml` runs real gates on `development`, `staging`, `production` (frontend install,
   tests, build; backend install, compile, full pytest suite including HTTP tests against a
   local uvicorn). `main-baseline.yml` re-verifies the published baseline on `main`.
   No `|| true` or equivalent masking is allowed.
4. **Secret protection.** `.env*` files are gitignored except `*.env.example`; local secret files
   use mode `0600`; values are never printed in logs, docs or reports.
5. **Document privacy.** User documents are never versioned or uploaded; tests and CI use only
   synthetic fixtures generated by `backend/fixtures_generator.py`.
6. **Operational independence.** Runtime, build, CI and development tooling do not require any
   coding-agent vendor service. Emergent was removed from the active codebase (see below).
7. **Bootstrap scope.** No product behavior, API, algorithm, OCR, detection rule, encryption,
   audit or data model was changed by this bootstrap.

## Emergent removal

Purgedoc was generated on the Emergent platform. The portability mission removed every active
dependency on it:

- Backend: `emergentintegrations` and the Emergent-hosted `litellm` wheel (never imported).
- Frontend: `@emergentbase/overlay` and `@emergentbase/visual-edits`, their CRACO wiring and
  the `DISABLE_EMERGENT_OVERLAY` variable.
- `frontend/public/index.html`: `emergent-main.js`, its error shim, and PostHog telemetry with
  session recording sent to `ap.emergent.sh`. No replacement telemetry was added.
- HTTP tests: the Emergent preview URL fallback and the `/app/frontend/.env` container path.
- Emergent platform metadata `.emergent/` and agent scaffolding: `test_result.md` protocol and the unused qabot
  `frontend/src/constants/testIds/` registry.
- CI: the filtered-requirements workaround.
- `backend/.env.example`: unused scaffold variables `MONGO_URL` and `DB_NAME`.

Kept as historical record only (not authority, not dependencies): `test_reports/`,
`memory/PRD.md` notes about past `testing_agent_v3` runs, and Git history.
`.emergent/` (Emergent image name and system package list only) was removed from the repository
and stays in `.gitignore`; the system requirements it listed are documented in
`.anclora/PRODUCTION_RUNTIME.md`.

Unused but public Python packages from the original scaffold (`motor`, `pymongo`, `boto3`,
`stripe`, `openai`, `google-genai`, `google-generativeai`, `google-api-python-client`, ...)
were kept on purpose: they do not depend on Emergent, and removing them is a separate
dependency-hygiene task.
